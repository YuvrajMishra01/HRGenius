# HRGenius — Database Design

Relational schema, Oracle-first. All DDL lives in Flyway migrations (`backend/src/main/resources/db/migration`). On real Oracle every column maps to the types below; H2 (Oracle mode) mirrors them for local dev.

## Conventions

- PKs: `NUMBER(19)` generated by sequence (IDENTITY on H2).
- Money: `NUMBER(12,2)` — mapped to `BigDecimal` in Java. Floating point is never used for money.
- Dates: `DATE`; timestamps: `TIMESTAMP`.
- All FKs indexed; unique keys where the domain demands (`USERS.EMAIL`, `EMPLOYEES.EMPLOYEE_CODE`, `EMPLOYEES.EMAIL`).

## ER Overview

```
USERS ─(1:1)─ EMPLOYEES ─(N:1)─ DEPARTMENTS ─(1:N)─ DESIGNATIONS
                  │  └─(self FK) MANAGER_ID → EMPLOYEES
                  ├─(1:N) ATTENDANCE
                  ├─(1:N) LEAVE_REQUESTS ─(N:1)─ LEAVE_TYPES
                  ├─(1:N) PAYROLLS
                  ├─(1:N) PERFORMANCE_REVIEWS (employee + reviewer)
                  └─(1:N) DOCUMENTS

CANDIDATES ─(1:N)─ JOB_APPLICATIONS ─(N:1)─ JOBS ─(N:1)─ DEPARTMENTS
                         └─(1:N)─ INTERVIEWS ─(N:1)─ EMPLOYEES (interviewer)

EMPLOYEES ─(1:1)─ ONBOARDINGS          USERS ─(1:N)─ NOTIFICATIONS
```

## Tables

| Column | Type | Constraints |
|---|---|---|
| ID | NUMBER(19) | PK |

### DEPARTMENTS
ID PK · NAME VARCHAR2(100) UNIQUE NOT NULL · DESCRIPTION VARCHAR2(255) · MANAGER_ID FK → EMPLOYEES (nullable, circular by design — assigned after employee exists)

### DESIGNATIONS
ID PK · TITLE VARCHAR2(100) NOT NULL · DESCRIPTION VARCHAR2(255) · DEPARTMENT_ID FK → DEPARTMENTS · UNIQUE (TITLE, DEPARTMENT_ID)

### JOBS
ID PK · TITLE VARCHAR2(150) NOT NULL · DESCRIPTION CLOB · DEPARTMENT_ID FK · LOCATION VARCHAR2(100) · EMPLOYMENT_TYPE CHECK · SALARY_RANGE VARCHAR2(60) · STATUS CHECK (DRAFT/OPEN/CLOSED) NOT NULL · POSTED_DATE DATE · CLOSING_DATE DATE

### CANDIDATES
ID PK · NAME NOT NULL · EMAIL NOT NULL · PHONE · RESUME_PATH VARCHAR2(255) · SKILLS VARCHAR2(500) · EXPERIENCE_YEARS NUMBER(4,1) · STATUS CHECK (NEW/SCREENING/SHORTLISTED/INTERVIEWED/SELECTED/REJECTED/HIRED) · CREATED_AT

### JOB_APPLICATIONS
ID PK · CANDIDATE_ID FK NOT NULL · JOB_ID FK NOT NULL · APPLICATION_DATE DATE NOT NULL · STATUS CHECK (APPLIED/SCREENING/SHORTLISTED/INTERVIEW/SELECTED/REJECTED) · REMARKS VARCHAR2(500) · UNIQUE (CANDIDATE_ID, JOB_ID)

### INTERVIEWS
ID PK · APPLICATION_ID FK NOT NULL · INTERVIEWER_ID FK → EMPLOYEES · INTERVIEW_DATE TIMESTAMP NOT NULL · MODE CHECK (ONSITE/ONLINE/PHONE) · STATUS CHECK (SCHEDULED/COMPLETED/CANCELLED) · FEEDBACK VARCHAR2(1000) · RESULT VARCHAR2(20)

### ONBOARDINGS
ID PK · EMPLOYEE_ID FK NOT NULL UNIQUE · JOINING_DATE DATE · STATUS CHECK (PENDING/IN_PROGRESS/COMPLETED) · COMPLETION_PERCENTAGE NUMBER(5,2) CHECK 0–100 · CHECKLIST CLOB (JSON of stage flags)

### ATTENDANCE
ID PK · EMPLOYEE_ID FK NOT NULL · ATTENDANCE_DATE DATE NOT NULL · CHECK_IN TIMESTAMP · CHECK_OUT TIMESTAMP · STATUS CHECK (PRESENT/ABSENT/HALF_DAY/LEAVE/HOLIDAY) NOT NULL · WORKING_HOURS NUMBER(4,2) · UNIQUE (EMPLOYEE_ID, ATTENDANCE_DATE)

### LEAVE_TYPES
ID PK · NAME UNIQUE NOT NULL · DESCRIPTION · YEARLY_LIMIT NUMBER(3) NOT NULL

### LEAVE_REQUESTS
ID PK · EMPLOYEE_ID FK NOT NULL · LEAVE_TYPE_ID FK NOT NULL · START_DATE / END_DATE DATE NOT NULL CHECK END≥START · REASON VARCHAR2(500) · STATUS CHECK (PENDING/APPROVED/REJECTED/CANCELLED) · APPROVED_BY FK → USERS · CREATED_AT

### PAYROLLS
ID PK · EMPLOYEE_ID FK NOT NULL · MONTH NUMBER(2) CHECK 1–12 · YEAR NUMBER(4) · BASIC_SALARY/ALLOWANCES/DEDUCTIONS/TAX/NET_SALARY NUMBER(12,2) NOT NULL · STATUS CHECK (DRAFT/PROCESSED/PAID) · UNIQUE (EMPLOYEE_ID, MONTH, YEAR)

### PERFORMANCE_REVIEWS
ID PK · EMPLOYEE_ID FK NOT NULL · REVIEWER_ID FK → EMPLOYEES NOT NULL · REVIEW_PERIOD VARCHAR2(20) · RATING NUMBER(1) CHECK 1–5 · STRENGTHS/WEAKNESSES/GOALS/COMMENTS VARCHAR2(1000) · STATUS CHECK (DRAFT/SUBMITTED/ACKNOWLEDGED)

### DOCUMENTS
ID PK · EMPLOYEE_ID FK NOT NULL · DOCUMENT_TYPE CHECK (RESUME/OFFER_LETTER/ID_PROOF/CERTIFICATE/EXPERIENCE_LETTER/OTHER) · FILE_NAME VARCHAR2(255) NOT NULL · FILE_PATH VARCHAR2(500) NOT NULL · FILE_SIZE NUMBER(12) · UPLOADED_AT TIMESTAMP

### NOTIFICATIONS
ID PK · USER_ID FK → USERS NOT NULL · TITLE VARCHAR2(150) · MESSAGE VARCHAR2(1000) · TYPE VARCHAR2(30) · READ_FLAG NUMBER(1) DEFAULT 0 · CREATED_AT

## Indexes

```
IX_ATT_EMP_DATE       ATTENDANCE(EMPLOYEE_ID, ATTENDANCE_DATE)  (also unique)
IX_LR_EMP             LEAVE_REQUESTS(EMPLOYEE_ID)
IX_LR_STATUS          LEAVE_REQUESTS(STATUS)
IX_EMP_DEPT           EMPLOYEES(DEPARTMENT_ID)
IX_APPS_JOB           JOB_APPLICATIONS(JOB_ID)
IX_APPS_STATUS        JOB_APPLICATIONS(STATUS)
IX_INT_APPL           INTERVIEWS(APPLICATION_ID)
IX_PAY_EMP_PERIOD     PAYROLLS(EMPLOYEE_ID, YEAR, MONTH)
IX_NOTIF_USER_READ    NOTIFICATIONS(USER_ID, READ_FLAG)
```

## Business Rules (enforced in service layer + constraints)

1. Employee code and email are globally unique.
2. A candidate can apply to a job only once (unique pair).
3. Attendance is one row per employee per day (unique pair).
4. Leave requests cannot overlap an already-approved request of the same employee.
5. Leave balance = LeaveType.yearly_limit − sum(approved days in current year).
6. Payroll is unique per employee per (year, month); recomputation only in DRAFT.
7. Net salary is always computed server-side: `basic + allowances − deductions − tax`.
8. Onboarding completion percentage is server-computed from checklist stages.
